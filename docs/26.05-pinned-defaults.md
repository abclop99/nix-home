# Pre-26.05 defaults pinned during the 25.11 → 26.05 upgrade

When this config moved from Home Manager 25.11 to 26.05 (commits `084c8c4`,
`b027adb`, `b7bf3dd`), several options whose **default value changed in 26.05**
were explicitly pinned to their pre-26.05 values. This keeps behaviour
identical and silences the per-build warnings.

All of these are gated on **`home.stateVersion = "23.11"`** (`home.nix`). The
state version is intentionally *not* bumped — bumping it to `"26.05"` would flip
every unpinned default at once. Because the values below are pinned explicitly,
they win regardless of `stateVersion`, so a future `stateVersion` bump is safe;
you can then drop pins one at a time as you choose to adopt each new default.

## How to adopt a pinned default later

Removing a pin does **not** adopt the new behaviour while `stateVersion` stays
`23.11` — the option just falls back to the (still old) default and the warning
returns. To actually adopt one, either:
- set the option explicitly to the new value, **or**
- bump `home.stateVersion = "26.05"` and remove that pin (the default then
  becomes the new value).

## The pins

| Option | Location | Pinned (old) value | New 26.05 default | Adopting later |
|---|---|---|---|---|
| `wayland.windowManager.hyprland.configType` | `modules/hyprland.nix` | `"hyprlang"` | `"lua"` | Rewrite the Hyprland config in Lua (large job). Also a prerequisite to re-enabling `catppuccin.hyprland` (see below). |
| `programs.firefox.configPath` | `modules/firefox.nix` | `".mozilla/firefox"` | `"${config.xdg.configHome}/mozilla/firefox"` | Move `~/.mozilla/firefox` → `$XDG_CONFIG_HOME/mozilla/firefox`, delete the old dir. Native-messaging hosts are **not** moved automatically. Tidiness only. |
| `gtk.gtk4.theme` | `modules/theme.nix` | `config.gtk.theme` (mirror) | `null` (GTK4 unthemed) | Adopting `null` drops Catppuccin from GTK4 apps — keep the pin unless you want that. |
| `xdg.userDirs.setSessionVariables` | `home.nix` | `true` | `false` | Set `false` only if nothing relies on `XDG_DESKTOP_DIR` / `XDG_DOWNLOAD_DIR` / … as env vars. |
| `services.home-manager.autoUpgrade.preSwitchCommands` | `modules/services.nix` | `[ "nix flake update" ]` | `[ ]` | Adopting `[ ]` stops the weekly auto-upgrade from running `nix flake update` before switching. |

## Related: catppuccin.hyprland disabled

`catppuccin.hyprland` was **dropped** (`modules/theme.nix`, commit `b7bf3dd`), not
pinned. On v26.05 it themes via an inline-lua value (`require('themes.catppuccin')`)
that only renders under `configType = "lua"`; under the pinned `"hyprlang"` it
emitted an invalid `colors { _var { … } }` block and broke Hyprland config
loading. This config references none of catppuccin's Hyprland colour vars, so it
was inert anyway. To use it again you would first adopt `configType = "lua"`.

## Worth revisiting (suggested priority)

1. **`autoUpgrade.preSwitchCommands = [ ]`** — strongest candidate. Matches the
   "narrow auto-upgrade" intent in `CLAUDE.md` (stop the weekly update from
   advancing *every* input, including the unstable/master ones).
2. **firefox XDG path** — optional; only if you want the profile under `~/.config`.
3. **hyprland Lua, gtk4 `null`, xdg vars `false`** — probably leave as-is (Lua is a
   large rewrite; the other two only remove functionality).
